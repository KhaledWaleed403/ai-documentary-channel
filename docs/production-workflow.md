# Production Workflow

Each stage has an output file and a gate that must pass before the next stage. Replace `NNN` with the episode number.

| # | Stage | Output | Gate |
| --- | --- | --- | --- |
| 1 | Research | `research/episode-NNN/sources.md`, `research-notes.md` | Core question defined; ≥ 2 credible sources per key topic |
| 2 | Fact-checking | `research/episode-NNN/claims.md` | Every claim has a source and status `verified`; disputed claims flagged or cut |
| 3 | Script | `episodes/episode-NNN/<version>/script.md` | Every factual line references a claim ID; read-aloud timing estimated |
| 4 | Storyboard | `episodes/episode-NNN/<version>/storyboard.json` | Every scene has narration, visual description, components and duration |
| 5 | Narration | Voiceover audio in `episodes/episode-NNN/<version>/assets/` | Final read recorded; scene timings updated from real audio |
| 6 | Animation | Compositions/scenes in `src/` | Plays in Studio; `npm run lint` passes; matches storyboard |
| 7 | Review | Notes in the episode folder | Accuracy, clarity, pacing, captions and accessibility checked |
| 8 | Publishing | Render in `renders/episode-NNN/<version>/`, thumbnail in `thumbnails/episode-NNN/Long/<version>/` (Shorts: `Shorts/<ShortName>/<version>/`), titles and settings in `publication/episode-NNN/` | Title, description (with sources), captions, chapters uploaded |

## Stage notes
1. **Research** — Start from primary sources (standards, papers, manufacturer docs, textbooks). Log every source with URL and access date.
2. **Fact-checking** — Break notes into atomic claims (`C001`, `C002`, …). Mark simplifications explicitly.
3. **Script** — Hook in the first 15 s, then whole → parts → flow → why it matters. Write for the ear.
4. **Storyboard** — One idea per scene. Note which inventory components each scene uses; list any new components needed.
5. **Narration** — One snippet per shot, generated and approved individually (see `episodes/episode-NNN/<version>/narration-snippets.md`). Takes live in `episodes/episode-NNN/<version>/assets/audio/vo/` as `shNN-takeNN.wav` and are never overwritten; `vo/manifest.json` records each take and which one is approved. Episode 001 uses Kokoro-82M `af_heart`, generated by `~/.luminexplain-kokoro/scripts/kokoro_snippet.py` in its own Python environment, outside the project. `src/data/episodeNNNNarration.ts` imports the approved takes and throws if a snippet, approval or file is missing or its text differs from `storyboard.json`. Renders only read these files. Export captions to `captions.srt` from the final audio. Retime shots to the audio by editing `startFrame`/`endFrame` (and `start`/`end`) in `storyboard.json`. Set `draft: false` only once the narration is attached.
5b. **Captions (required for every video)** — Generate captions from the final narration takes with `scripts/audio/build-ep001-captions.py`, which snaps phrase boundaries to measured pauses. It writes `captions.json` (burned-in cues) and `captions.srt` (upload file) into the video's version folder. Shorts burn in captions with `src/components/Captions.tsx`: white text on a translucent navy backing, a few teal/amber accent words, block bottom at y 1520, and the scene layer scaled toward the top so captions never cover the picture. Long-forms keep a clean picture and get only the `.srt`. Proofread every cue against the narration. Put a copy of the `.srt` next to the render. Re-run the script after any audio edit, and make a new version for any caption fix, never overwriting an earlier render. When publishing, keep YouTube's auto-captions from overlapping the burned-in ones. Details: `episodes/episode-001/shorts/captions.md`.
6. **Animation** — Build new reusable components first (add to `docs/component-inventory.md`), then episode scenes.
7. **Review** — Watch at full size and phone size; re-check any claim changed since stage 2.
8. **Publishing** — Render only the final cut, then master its loudness into a separate file (video stream copied, audio to −14 LUFS / −1.5 dBTP): `npx remotion ffmpeg -i renders/episode-NNN/<version>/<name>.mp4 -c:v copy -af loudnorm=I=-14:TP=-1.5:LRA=11 -ar 48000 -c:a aac -b:a 320k renders/episode-NNN/<version>/<name>-master.mp4` (if AAC lands a hair above −1.5 dBTP, use `TP=-1.7`). Check it with `npx remotion ffmpeg -i <file> -vn -af loudnorm=print_format=json -f null -`. After launch, log performance in `analytics/` and feed lessons back into the brief.
